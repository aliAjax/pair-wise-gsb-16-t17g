# hxwl-01 听力验配复调闭环

门店听力师工作台：复调预约 → 试听机借用互斥 → 试听分频增益与满意度版本链 → 耳道红肿/未消毒转待复核与耳模返工 → 改期释放 → 刷新一致性审计。

## 技术栈

React 19 + Vite + TypeScript（无后端，状态持久化于浏览器 localStorage）

## 本地运行

```bash
npm install
npm run dev        # http://localhost:5101
```

其他命令：

```bash
npm run typecheck  # 类型检查
npm run selftest   # 领域逻辑端到端自测（30+ 断言）
npm run build      # 生产构建
```

## 业务闭环与规则

### 1. 复调预约（客户 / 左右耳 / 试听机 / 时段）
- 预约记录客户、左右耳（绑定耳模）、试听机、开始/结束时段。
- 老客户复调沿用同一 `caseId`，新预约在链上递增序号；新客户可建档。
- **同一试听机时段互斥**：与「已预约 / 待复核 / 已完成试听」的借用单重叠时拒绝创建
  （端点相接允许），不写入任何数据，仅把冲突记入冲突清单。
- 耳模只能选本客户、同耳侧的耳模；跨客户绑定在提交前拦截。

### 2. 试听机借用
- 设备占用口径：已预约、待复核、已完成试听均视为借出；
  「改期中（已释放）」与「已改期」旧单不占位。
- 设备面板提供时间轴与任意时段占用探测。

### 3. 试听记录：分频增益 + 满意度 + 版本链
- 六频段（250/500/1K/2K/4K/8K）增益，左右耳分别记录。
- 满意度 0–100；**低于 80 必须填写「调整」与「新建版本原因」**，否则不予提交。
- 每次提交按耳在该 case 的版本链上新建版本（父指针串联），**旧参数原样保留**、
  标记为已替代，每耳始终恰有一个当前版本。新版本默认带出当前参数作为调参起点。

### 4. 安全红线：耳道红肿 / 耳模未消毒
- 试听提交时硬校验：任一侧耳道红肿或耳模未消毒，**不生成任何试听结果/版本**，
  预约整体转入「待复核」并留存现场快照，同时自动开立耳模返工单（耳模进入返工中）。
- 返工完成可记录处理备注与消毒结果；拦截原因全部消除后预约自动恢复「已预约」。

### 5. 改期：先释放设备，再确认新时段
- 改期分两步：先把旧单设备占用释放（旧单进入「改期中」，原值保留），
  释放后原时段立即可被其他客户借用；再选择新设备/时段确认。
- 新时段同样做设备互斥校验：冲突则不改期、只记冲突（含**原值**），旧单保持释放态。
- 确认后旧单标记「已改期」，新单以同一 `caseId` 承接，同一对耳模沿用，
  试听与参数版本链连续。可撤销改期恢复原占用（若原时段已被占则只能选新时段）。

### 6. 冲突清单
- 列出：编号、动作（新预约/改期）、发起客户、试听机、申请时段（未生效）、
  被占用客户/预约、占用时段、改期原值。

### 7. 刷新一致性
- 所有状态持久化到 localStorage，刷新后保留。
- 「刷新并复核闭环」执行 8 类审计：设备占用两两不重叠、改期草稿↔释放单对应、
  耳模引用完整、待复核↔返工单状态、试听↔版本引用、版本号连续/父指针/唯一当前版本、
  冲突引用有效、已完成单必有试听。异常逐条列在审计区。

src/types.ts                 领域类型

src/components/
  BookingForm.tsx            复调预约表单（含实时冲突预览）
  DeviceBoard.tsx            试听机占用时间轴/时段探测

  TrialModal.tsx             分频增益/满意度/安全校验试听登记
  RescheduleModal.tsx        释放→改期两步弹窗（原值对比）
  ReworkPanel.tsx            耳模返工闭环
  ConflictPanel.tsx          冲突清单（客户/设备/时段/原值）
  AuditPanel.tsx             刷新一致性审计与数据快照
  Metrics.tsx / LogStream.tsx 指标与操作流水
scripts/selftest.ts          领域逻辑端到端自测
